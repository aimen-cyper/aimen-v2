# سياسة التسعير والتقريب (v1.3.1)

> كل ما هنا مأخوذ من الكود ومحروس باختبارات (`tests/unit/test_money.py` وما حولها، و`tests/integration/test_v131_pricing.py`).
> **لا float في أي حساب مالي.** كل المبالغ أعداد صحيحة بوحدة = 0.0001 من العملة (`MONEY_SCALE = 10_000`).

## 1) مصدر كل رقم

| الرقم | أين يُحسب/يُخزَّن | ملاحظة |
|---|---|---|
| تكلفة المزود/1000 بعملة المزود | يأتي من API المزود عند المزامنة/الاستيراد | لا يُخزَّن بعملته؛ يُحوَّل فوراً |
| تكلفة المزود/1000 بعملة النظام | `services.provider_price_per_1000_units` | = `to_system_units(سعر المزود, exchange_rate)` |
| سعر البيع/1000 | `services.price_per_1000_units` | = `price_with_margin` عند الاستيراد، ثم بيد الأدمن |
| لقطة سعر الطلب | `orders.price_per_1000_snapshot_units` | تُنسخ لحظة إنشاء الطلب ولا تتغير أبداً |
| تكلفة الطلب | `orders.cost_units` | = `order_cost_units(لقطة السعر, الكمية)` وهي المخصوم فعلاً |
| المسترجَع | `orders.refund_amount_units` + حركات `refund/partial_refund` | يطابقان دائماً (تدقيق `audit_ledger`) |
| `exchange_rate` | `providers.exchange_rate` (لكل مزود) | **هو الذي يُسعَّر به** |
| `usd_rate` | إعداد `usd_rate` | **للعرض فقط** (مقابل الدولار للعميل)، لا يدخل في أي حساب. فارغ/فاسد ⇒ تُخفى أسطر «$» ولا قيمة احتياطية في الكود |

> سبب شائع لأسعار «غير متناسبة»: اختلاف `usd_rate` (العرض) عن `exchange_rate` (التسعير). تحذّر منه «🗺 خريطة المزودين»
> و`pricing_audit`. لا يغيّر أيٌّ منهما سعراً تلقائياً.

## 2) قواعد التقريب (كلها `ROUND_HALF_UP` إلا الاسترجاع الجزئي)

| العملية | المعادلة | اتجاه التقريب |
|---|---|---|
| تحويل عملة المزود | `round_half_up(units × exchange_rate)` — **مرة واحدة** عند التحويل | نصف لأعلى |
| السعر بالهامش | `(cost × (100 + margin%) + 50) // 100` | نصف لأعلى |
| تكلفة الطلب | `(price_per_1000 × quantity + 500) // 1000` | نصف لأعلى |
| استرجاع جزئي | `(cost × remains) // quantity` | **لأسفل** = لصالح الشركة بأقل من وحدة (0.0001) |
| مقابل الدولار (عرض) | `round_half_up(amount ÷ usd_rate, 4)` ثم خانتان (أربع للمبالغ الصغيرة) | للعرض فقط |

القيم الوسيطة لا تُقرَّب أكثر من مرة، وكل التقريب أعداد صحيحة/`Decimal`.

## 3) ما يضمنه النظام

1. **تثبيت تاريخي:** تغيير `exchange_rate` أو سعر الخدمة أو الهامش لا يغيّر `cost_units` ولا لقطة أي طلب قائم (اختبار R14).
2. **تنبيه لا تعديل:** بعد تغيير سعر الصرف يُنبَّه الأدمن (`providers.set_currency`) إلى خدمات **ستصير** بهامش سالب عند المزامنة التالية؛ لا يتغير أي سعر.
3. **منع اختياري:** إعداد `block_negative_margin` (الافتراضي `false`) إن فُعِّل يرفض إنشاء طلب على خدمة سعر بيعها أقل من تكلفتها.
4. **تدقيق مستقل للقراءة فقط:** `python -m scripts.pricing_audit --db نسخة.db` (يعيد حساب كل طلب من لقطته، ويبحث عن مصدر أي مبلغ بـ`--find`)، و`audit_ledger` يُنبّه إن لم تطابق التكلفةُ لقطةَ السعر.

## 4) إجراء عند ظهور سعر مريب (مثل 43.41 أو 94.74)

1. خذ **نسخة** من القاعدة (لا تشغّل الأداة على الملف الحي إن أمكن).
2. `python -m scripts.pricing_audit --db نسخة.db --find 43.41 36.53 3.98 94.74` — يبيّن أهو سعر خدمة أم تكلفة أم طلب أم حركة، وبأي سعر صرف.
3. قارن «الأصلي عند المزود» (عمود الأداة) بلوحة المزود؛ إن اختلف فالمشكلة في `exchange_rate`، وإن توافق فالأمر هامش/تقريب.
4. صحّح السعر أو الصرف من لوحة الأدمن (مُدقَّق)، ولا تُعدّل القاعدة يدوياً.
